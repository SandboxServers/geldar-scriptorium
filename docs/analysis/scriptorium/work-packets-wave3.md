**SDK facts, verified by a scratch run on Node 22.23.2 (a coder relies on them and may skip re-proving them):**
- The tool schemas come from the contract as JSON Schema, not zod, so the server uses `McpServer` and sets handlers on its low-level `.server`: `const mcp = new McpServer({ name, version }, { capabilities: { tools: {}, resources: {}, prompts: {} } }); mcp.server.setRequestHandler(ListToolsRequestSchema, ...)`. (`Server` itself is marked `@deprecated` in the typings; `McpServer.server` is the supported door.) Imports: `@modelcontextprotocol/sdk/server/mcp.js`, `.../types.js` (`ListToolsRequestSchema`, `CallToolRequestSchema`, `ListResourcesRequestSchema`, `ReadResourceRequestSchema`, `ListPromptsRequestSchema`, `GetPromptRequestSchema`, `isInitializeRequest`), `.../server/streamableHttp.js` (`StreamableHTTPServerTransport`), `.../client/index.js` (`Client`), `.../client/streamableHttp.js` (`StreamableHTTPClientTransport`).
- A plain `node:http` server works: per session, `new StreamableHTTPServerTransport({ sessionIdGenerator: () => randomUUID(), onsessioninitialized })`, `await mcp.connect(transport)`, then `await transport.handleRequest(req, res, parsedBody)`. Requests carry `mcp-session-id` after `initialize`. No Express or Hono is needed.
- A client sends the token with `new StreamableHTTPClientTransport(url, { requestInit: { headers: { Authorization: 'Bearer <token>' } } })`.
- **The SDK client's default request timeout is 60 s.** A `wait` can last 240 s, so every client `callTool` for `wait` passes `{ timeout: 260_000 }` as its third argument. (The template's `.mcp.json` already sets 300 000 ms for the real CLI.)
- A handler receives `extra.signal` (aborted when the client cancels the request). Tool errors are returned as `{ isError: true, content: [{ type: 'text', text }] }`.
- stdout belongs to nothing here (HTTP server), but never log tokens, request bodies or headers. Logs are one JSON line per event to stderr.

**Contract facts (geldar `contract/`, read 2026-11-08):** schemas are JSON Schema 2020-12 files named `*.schema.json` with a `$id` of `https://geldar.dev/schemas/<file>`; `contract/scripts/generator.ts` builds `src/generated/{types.ts,validators.js,validators.d.ts}` as a pure function of the schema files (sorted, no timestamps), and `findStale()` is the drift check. Ajv runs with `strict: true`, so every schema that uses `properties` or `required` also says `"type": "object"`, and unknown keywords (`x-...`) are errors. A titled schema gets one validator named after the title and one type; an **untitled** schema (like `common.schema.json`) gets a type for every `$defs` entry. `thought.schema.json` already defines `Intent` and `Action` under `$defs` and `common.schema.json` defines `ActionId`, `IntentId`, `ItemName`, `LifeId`, `WorldTick`. Public API is `contract/src/index.ts`; each validator returns `ValidationResult<T>` (`{ ok: true, value } | { ok: false, errors: string[] }`).

**Windows and Linux (the geldar-side toolchain differs; Linux CI is the arbiter):**
- Windows with PowerShell 7 is the author platform; CI runs Linux. Run everything through `./geldar.ps1` (it puts a pinned `pnpm` on PATH). CI runs `pnpm` directly.
- Docker tests need Linux containers. `dockerReady()` (SC-33) is true only when `docker info --format {{.OSType}}` prints `linux`. Locally it skips with a warning; with `CI=true` a missing Docker is a failure. Open a draft PR for SC-33 early and read the CI log to confirm the suite ran.
- Bind-mounted files: on Windows `chmod` is a no-op; on a Linux runner `mkdtemp` makes mode 0700 and files 0600, owned by the runner's uid, which the container's uid 1000 cannot read. Test helpers `chmodSync(file, 0o644)` and directories `0o755` before mounting.
- Timers on Windows tick at about 15 ms: never assert a duration under 50 ms, and give timing assertions generous margins (every real-time bound below has at least 2x slack).
- Servers in tests listen on `127.0.0.1` port `0` and read the real port back. Never a fixed port, never `0.0.0.0` in a test. Paths are built with `node:path` and `fileURLToPath(import.meta.url)`, temp dirs with `mkdtempSync(join(tmpdir(), 'mcp-mock-'))`, removed in `afterEach`.
- Files are LF. Generated files must be byte-identical on both platforms (the generator already guarantees this; do not add `os.EOL` or locale-dependent sorting).

  ```ts

    tokens: TokenTable;
    /** Builds the MCP server for one new session. `signal` aborts when the session ends or is superseded. */
    createSession: (playerId: string, signal: AbortSignal) => McpServer;
  ```

  Behavior, in this order for every request:
  1. The path must match `^/p/([a-z][a-z0-9-]{1,38})$` exactly (no trailing slash, no query handling beyond ignoring it); otherwise 404 before anything else.
  2. `Origin` header: if present and its hostname is not `127.0.0.1`, `localhost` or `[::1]`, answer 403 (DNS-rebinding guard). Absent is fine (CLI clients send none).

  5. Sessions. A `POST` whose body satisfies `isInitializeRequest` starts a new session: if the player already has one, **supersede it first**: abort its signal, wait for its in-flight handlers to return (track a count; at most 1 s), then close its transport and server, and remember its session id in a bounded set (at most 100 ids per server, oldest dropped) of superseded ids. Then create the transport (`sessionIdGenerator: randomUUID`), the `McpServer` from `createSession(playerId, signal)`, connect, handle the request. Any other request needs a known `mcp-session-id` belonging to *this* player: unknown id gives 404 with JSON-RPC error message `session_not_found`; an id in the superseded set gives 404 with `session_superseded`; no id on a non-initialize request gives 400 `missing_session`; an id belonging to another player's session gives 404 `session_not_found`. `DELETE` with a valid id ends that session (abort, close, forget).
  6. A superseded or closed session's pending request must end: aborting its signal is how the world cancels a `wait`. (SDK clients treat a 404 on a live session as "re-initialise", so two clients on one player supersede each other in a loop; the README, SC-33, says so.)

  ```ts
  export interface Clock { nowMs(): number; sleep(ms: number, signal?: AbortSignal): Promise<void> }
  export class RealClock implements Clock {}       // Date.now and setTimeout; an aborted signal rejects with its reason and clears the timer
  export class FakeClock implements Clock {        // starts at 0 (or a given start)
    advance(ms: number): Promise<void>;            // moves time forward, firing due sleeps in time order
  }
  export const TICKS_PER_DAY = 24000;
  export function ticksPerSecond(dayLengthSeconds: number): number;      // TICKS_PER_DAY / dayLengthSeconds
  export function tickAt(elapsedMs: number, dayLengthSeconds: number): number;   // floor
  export function msAt(tick: number, dayLengthSeconds: number): number;          // ceil, the first ms at which tickAt >= tick
  ```

  `FakeClock.advance`: loop while the earliest pending sleep is due at or before the target: set `now` to its time, resolve it, then `await new Promise((r) => setImmediate(r))` so awakened code runs before the next timer; finally set `now` to the target. - **`wake.ts`** (pure; no clock, no I/O). Types and the one function:

  ```ts
  export type WakeReason = 'directly_addressed' | 'goal_completed' | 'precondition_failed' | 'unexpected_damage'
    | 'new_agent_nearby' | 'proposal' | 'day_night' | 'intent_run_too_long' | 'timeout';
  export interface WakeEvent { seq: number; atMs: number; kind: 'speech' | 'damage' | 'agent_approached' | 'proposal' | 'day_night' | 'intent_finished' | 'reflex';
    addressed?: boolean; distance?: number; outcome?: 'completed' | 'failed' | 'limit_reached'; failure?: 'precondition_failed'; wakeOn: string[] | null }  // wakeOn: the running intent's wake_on when the event happened, null if no intent
  export interface WakeConfig { minSpacingMs: number; intentRunTooLongMs: number }
  export interface SuppressedWake { seq: number; kind: string; reason: 'overheard_chatter' | 'not_in_wake_on' | 'not_in_interests' | 'min_spacing' | 'reflex'; atMs: number }
  export interface WakeDecision { wake: { reason: WakeReason; seqs: number[] } | null; suppressed: SuppressedWake[]; recheckAtMs: number | null }
  export function evaluateWake(i: { events: WakeEvent[]; intentStartedMs: number | null; interests: readonly string[]; nowMs: number; lastWakeMs: number | null; config: WakeConfig; alreadySuppressed: ReadonlySet<number> }): WakeDecision;
  ```

  Rules, per event, in this order (spec 5.3.2):
  1. `reflex` is never a candidate: suppressed `reflex`.
  2. `speech` not `addressed` is chatter: suppressed `overheard_chatter`. Addressed speech has reason `directly_addressed`, interest `directly_addressed`, and passes `wake_on` only if it lists `directly_addressed`.
  3. `damage`: reason `unexpected_damage`, interest `damage`, `wake_on` needs `unexpected_damage`. `agent_approached`: reason `new_agent_nearby`, interest `agent_approached`, `wake_on` needs an entry `new_agent_within_N` with `distance <= N`. `proposal` and `day_night`: reasons of the same name, interests of the same name, and with a running intent they are suppressed `not_in_wake_on` (no `wake_on` value names them).
  4. `intent_finished`: always a candidate whatever `wakeOn` says (owner call 3), and exempt from rules 5 and 6: `completed` gives `goal_completed`, `failed` with `failure: 'precondition_failed'` gives `precondition_failed`, `limit_reached` gives `intent_run_too_long`. Its interest is `intent_finished`.
  5. A candidate whose interest is not in `interests` is suppressed `not_in_interests`, except `intent_finished`, which no `interests` list can suppress. With `wakeOn === null` (no intent) the `wake_on` test is skipped.
  6. Surviving candidates: if `lastWakeMs !== null` and `nowMs - lastWakeMs < minSpacingMs` **and no surviving candidate is `intent_finished`**, nothing wakes (an intent end ignores the spacing, since nothing is left running; the fallback and the principle are unchanged); each surviving event not in `alreadySuppressed` is recorded `min_spacing`, and `recheckAtMs = lastWakeMs + minSpacingMs`. Otherwise the wake reason is the highest in this priority: `directly_addressed`, `precondition_failed`, `goal_completed`, `unexpected_damage`, `intent_run_too_long`, `new_agent_nearby`, `proposal`, `day_night`; `seqs` lists all surviving events.
  7. With no wake and `intentStartedMs !== null`: the **fallback**. If `nowMs - max(intentStartedMs, lastWakeMs ?? 0) >= intentRunTooLongMs`, wake with `intent_run_too_long` (and `seqs: []`); otherwise `recheckAtMs` is the earliest of its own due time and any spacing recheck.
  Suppressed records for events in `alreadySuppressed` are not returned again (the caller keeps the set).

  - `toPlayerEvents(events: SimEvent[]): McpPlayerEvent[]`: addressed speech gives `speech_to_me` ("Someone spoke to you."), all overheard speech in the span collapses to **one** `conversation_digest` ("N lines overheard.", `seq` of the last of them), `damage` "You took N damage.", `agent_approached` "Someone came within N blocks.", `proposal` "A proposal was put forward.", `day_night` "Dawn." or "Dusk.", `intent_finished` "Your intent finished." / "Your intent failed: precondition_failed." / "Your intent ran out of time.", `reflex` "Your body ate on its own." No text ever contains a neighbour's name or words.
  - `worldText(speechEvents: SimEvent[], extra?: { signs?: string[]; book?: { title: string; text: string } }): UntrustedWorldText`: the last 40 of the given speech events as `speech: [{from, text}]` (clipping `from` to 32 and `text` to 512), plus `signs` and `book` when given. `wait` passes the speech events with `seq` greater than its cursor; `look` passes the last 40 speech events in the log; `sleep` passes those since its mark.
  - `snapshotOf(sim: PlayerSim, scenario: Scenario): Snapshot`: the one mapping from sim to `buildSnapshot`'s `SnapshotParams` (SC-31b), with `heard: []`: `agent_id` from the character `life_id`; `shard` a fixed `baseline`; `revision` and the snapshot counter per-player counters that rise by 1 on each call; `day` and `timeOfDay` from the tick of day; `position` from the scenario character; `health` a constant 20 (cosmetic); `food` and `inventory` from the sim; `neighbours` from the scenario with the distance computed from the positions; `plan` from the running intent (or none). `look` and `wait` both call it.
  - `fitResult(result, maxBytes = 16000)`: while `Buffer.byteLength(JSON.stringify(result)) > maxBytes`, drop the oldest event, then the oldest speech line, then (sleep only) cut `book.text` from the front; set `dropped_events` (wait) to the count of events dropped (plus whatever the log reported). Returns the result. Applied to `wait` and `sleep`.
- **`wait.ts`: `waitTool(hub, ctx, input): Promise<WaitResult>`** (types from `@geldar/contract`). Algorithm, exactly:
  1. `fromSeq`: `decodeCursor(input.cursor)` when given (`null` or greater than `lastSeq()` throws `ToolError('bad_cursor', 'That cursor is not valid.')`), else `lastSeq()`. `interests` default is all six. `deadline = clock.nowMs() + max_seconds * 1000`.
  2. Loop: `now = clock.nowMs()`; `sim.syncTo(now)`; call `evaluateWake` with the events after `fromSeq` **whose `atMs` is greater than `sim.lastWakeMs`** (older events are still returned in `events`, but a retry cannot wake on what an earlier return already woke for) mapped to `WakeEvent`, `intentStartedMs` (the running intent's start in real ms, or `null`), `sim.lastWakeMs`, `sim.suppressedSeqs`; record every returned suppression through the hub and add its seq to `suppressedSeqs`. A wake gives `reason`; `now >= deadline` gives `timeout`; a `ctx.signal` abort throws `ToolError('session_superseded', 'Another session took over this player.')`. Otherwise `await clock.sleep(min(pollMs, deadline - now, recheckAtMs - now, nextScheduledMs - now), ctx.signal)` (each term only if finite, at least 1 ms).
  3. On return: `sim.lastWakeMs = now` (**for every return, a timeout included**); the result holds `snapshot` (`buildSnapshot` from SC-31b, `heard: []`), `events: toPlayerEvents(eventsAfter(fromSeq))` keeping only the newest 200 (the schema caps `events` at 200; the rest count in `dropped_events`), `cursor: encodeCursor(lastSeq())`, `wake_reason`, `dropped_events`, `untrusted_world_text: worldText(speech events after fromSeq)`, `note`, then `fitResult`.
  The held events of a `min_spacing` hold are still delivered in `events` when the wait later returns (nothing lost, nothing duplicated).
