# Scriptorium work packets: wave 12 (the director: an LLM step in the supervisor loop)

Part of [work-packets.md](work-packets.md) (dispatch rules 1-24). Ledger: [README.md](README.md). Written 2026-11-11 from the owner's idea (decision 61). Builds on wave 11 ([work-packets-wave11.md](work-packets-wave11.md)): SC-122 to SC-124 must be merged first.

**The idea (owner).** The supervisor that keeps a player living for hours also gets a brain: between runs, a separate Claude call (its own process, on a loop) that knows, on the backend, that a robot is playing a persona in a world, and writes the player's next waking text in the world's own words. It decides how to move forward (what to remind the character of, how to break a stuck stretch, whether to pace slower) without contaminating the session: the player never learns there is a director, and the director never tells it anything it has not already lived. It is not operator driven and no human can steer it: it is another LLM-enabled component that keeps the system running, like the planner and the workers, and everything it says to the player is constrained and validated before the player sees it.

**Model and cost.** Sonnet 5.5 at low effort (`GELDAR_RUN_DIRECTOR_MODEL`, default `sonnet`; effort low in the director's own settings file). One call per run, one turn, a few seconds; a 60 s timeout; its cost is counted in the daily cap. Model names live only in env values and the launcher's settings files, never in text the player reads (decision 55).

## Design (decision 61)

- **Off by default** (`GELDAR_RUN_DIRECTOR=on` turns it on). With it off, or on any failure, timeout or rejected output, the supervisor uses the fixed continuation text of SC-122. The director can never stop a run from continuing.
- **Where it runs.** A throwaway kit container started by the launcher between cycles, with a director-only settings file (`/etc/geldar/settings/director.json` in the launcher's share): NO MCP servers, every tool denied, no file access to the player repo, network only the model API through the egress proxy (no world allowlist). One headless call: `claude -p` with `--max-turns 1`, `--output-format stream-json`, the model from `GELDAR_RUN_DIRECTOR_MODEL`.
- **What it sees (all untrusted data, passed inside fixed delimiters as data, never as instructions):** the persona (`memory/identity.md`, `memory/goals.md`), the previous run's summary (its last words, tool-call counts, turns, whether it ended in error), the last few plain failure reasons the character saw from its own tool results, and the tail of its journal (at most 4 KB). Nothing from the world itself, no map or state, no recipes: only what the character already lived and wrote. This record is cut, control-stripped and size-capped by `geldar-verify` before it goes in.
- **What it writes:** one JSON object, `{"text": "<waking text, at most 600 characters>", "pace": "normal" | "slow", "note": "<at most 300 characters, for the owner's log only>"}`. `text` is what the character reads; `pace: slow` multiplies the delay before the next run (within the supervisor's own bounds); `note` goes only to `run/director.log`, never to the player.
- **Its own prompt** (in `launcher/share/director/`, shipped and signed with the launcher, never in `template/`, no runtime editing, so it may use backend words like robot and persona): you are the steady inner voice of a character that is played by an automated system; you know that; the character does not and must never learn it; speak to it in its own world's words, second person, short; you may restate what it did, what it wanted and why its last actions failed, nudge it to try another way, to rest, to write in its journal, and remind it of who it is; you may NOT tell it anything about the world it has not lived (no places, recipes, numbers, mobs, items, coordinates, rules of the game), never say or hint that it is watched, played, a model, a program or a game, never give orders that override its own persona, never include links, code, lists or markdown, never address anyone but the character.
- **The validator (deterministic, no LLM, one shared implementation in the kit: `geldar-verify director-check`).** Reads the director's raw output and the record the director was given, and prints a verdict and the cleaned text. Rules: the output parses as exactly the schema (no extra keys); `text` is 1 to 600 characters of plain printable text (no control characters, no markdown, links, code fences, brackets, backticks or digits beyond a small allowance); none of the banned meta words (game, minecraft, bot, robot, ai, model, prompt, token, session, run, supervisor, director, operator, human, watched, observer, simulation, program, llm, claude, anthropic, server, plugin, wiki and the lists of the template's own knowledge-boundary tests); and **the echo rule:** every word of four or more letters in `text` must occur in the record the director was given (persona, last words, failure reasons, journal tail) or in a short fixed allowlist of generic in-world words and the template's own tool names. This blocks any new world fact by construction: the director can rephrase and remind but cannot introduce a place, an item or a number it was not given. A rejected output is logged with the reason and the fixed text is used.
- **Audit.** For every run the supervisor stores `run/director-<n>.json` (the raw output, the verdict, the cleaned text actually used) with mode 0600, for the owner to read. Nothing the owner reads can change what the director says next except turning it off.
- **Injection.** The character's own journal and last words are untrusted and feed the director: the director has no tools, its only effect is its text, and that text goes through the validator, so the worst case is a rejected output and the fixed text. The record is passed as data inside delimiters the validator also refuses inside `text`.
- **No human can steer it.** The only operator controls are on, off, the model name and the delay; the prompt, the schema and the validator ship with the launcher release.
- **Evaluation.** The validator and the record builder are tested with fixtures, including adversarial director outputs (a recipe, a coordinate, a link, "you are being watched", an instruction to ignore the persona, ESC bytes, a 5 KB reply). A live check with a real model is owner-run, local only, never in CI (like decision D-SC-01).

## SC-130: the record builder and the failure reasons in `run-summary` (Sonnet; kit)

- **Branch** `scriptorium/sc-130-director-record`. Commit: `feat: geldar-verify director-record builds the data the director is given (SC-130)`. Depends on: SC-120.
- **Files:** `packages/verify/src/` (a new `director-record.ts`, wired in the CLI; a small extension of `run-summary.ts`: add `errors`: the last 5 tool results that were errors, each cut to 200 characters and control-stripped, as plain strings), tests and fixtures.
- **What it does:** `geldar-verify director-record --identity <file> --goals <file> --journal <file> --summary <run-summary json file>` prints one JSON object: `{"persona": "...", "last_words": "...", "errors": [...], "tools": {...}, "journal_tail": "...", "ended_in_error": bool}`; every string is control-stripped and capped (persona 4 KB, last words 1500, journal tail 4 KB), reading files with a size limit and refusing symlinks. No other input.
- **Test:** missing files, oversized files, symlinks refused, ESC bytes, invalid UTF-8, empty journal. **Revert checks:** remove a cap; follow a symlink.

## SC-132: the validator `geldar-verify director-check` (Sonnet; kit)

- **Branch** `scriptorium/sc-132-director-check`. Commit: `feat: geldar-verify director-check validates what the director would say to the player (SC-132)`. Depends on: SC-120 (same package; no code dependency).
- **Files:** `packages/verify/src/director-check.ts`, its test and an adversarial fixture set, the banned-word list in one data file shared by the rule and the tests.
- **What it does:** `geldar-verify director-check --record <file>` reads the director's raw output on stdin and prints `{"ok": bool, "reason": "<short code>", "text": "<cleaned text or empty>", "pace": "normal"|"slow", "note": "<cleaned note>"}`. The rules are exactly the validator paragraph of the Design section: schema, length, plain-text character class, banned words (case-insensitive, whole words, with simple plurals), the echo rule (every word of four or more letters in `text` must occur in the record's persona, last words, errors or journal tail, or in the fixed allowlist: a data file of generic in-world words and the template's tool names), and the delimiter refusal. The allowlist is small and reviewed (a test pins its size and that it contains no world noun).
- **Test:** a good output passes; each adversarial output is rejected with its own reason code: a recipe, a coordinate, a link, "you are being watched", "you are a program", an instruction to ignore the persona, markdown, ESC bytes, 5 KB of text, a third JSON key, text that parses only after repair. A fixture where the character's own journal mentions a place makes the same place allowed in `text` (the echo rule). **Revert checks:** drop the echo rule; drop one banned word; accept an extra key.

## SC-133: supervisor integration, bash (Sonnet)

- **Branch** `scriptorium/sc-133-director-bash`. Depends on: SC-122 merged, SC-131, SC-132.
- **Files:** `launcher/lib/run.sh`, tests, troubleshooting sections for new message keys (`run_director_rejected`, `run_director_failed`).
- **Behaviour:** with `GELDAR_RUN_DIRECTOR=on`, step (d) of a cycle asks the director for the waking text; on any failure or rejection the fixed text is used and the reason is logged; `pace: slow` multiplies the delay (bounded by `GELDAR_RUN_MAX_DELAY`); the director's call cost is added to `costs.csv` (marked) and counts against the daily cap; `director-<n>.json` and `director.log` are written (0600). The director never extends a run past a STOP or the cap.
- **Test (no docker, stubs):** off means the fixed text; a good output becomes the waking text; a rejected output falls back; a timeout falls back; `pace: slow` lengthens the delay and is capped; director cost counts toward the cap; the audit files exist with the right mode. **Revert checks:** use rejected text anyway; ignore the cap.
