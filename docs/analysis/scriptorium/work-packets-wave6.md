### SC-60b2: Collision case table and suite (gate for SC-60k and SC-60l)

- **Branch** `scriptorium/sc-60b2-collision-tables`, worktree `sc-60b2`. Commit: `test(launcher): shared case table for the start-tree case-collision check`. Model: Haiku. Depends on: wave 5. Parallel with SC-60a and SC-60b1.

No product code.
- **The collision rule (decision 28), about the end tree only.** `fold(p)` is ASCII lowercase (the same as the path rule; non-ASCII never passes it). `S` is the set of file paths in the START tree and `E` the set in the tree at the incoming ref. For a path set `P`, `M(P)` is its members: the file paths and every proper directory prefix of each (`memory`, `memory/journal`, and so on). The check **rejects** when there are `a`, `b` in `M(E)` with `fold(a) == fold(b)`, `a != b` (different literal spelling) and at least one of them **not in `M(S)`** (the session introduced it). Two spellings that were both already in the start tree never collide; a spelling that exists only in `S` and was deleted in `E` is not in `M(E)`, so a case-only rename is allowed. A file replacing a directory of the same literal name is not a collision (git and the path rule handle it).
- **`collision-cases.json`:** at least 24 rows `{name, start: string[], add: string[], delete?: string[], collides: boolean, launcher?: false}` (the end tree is `start` minus `delete` plus `add`). Rows the real re-check cannot receive carry `"launcher": false`: `host_recheck` runs the path rule first, which refuses `memory/a.MD`, `Memory/...` and any path outside `memory` and `skills` with `ok=false` for a path-rule reason, so those rows feed only `refCollides` (the suite skips them). Every other row is a path the path rule allows. Required rows: `memory/Identity.md/x.md` over start `memory/identity.md` (`collides: true`; the path rule at `recheck.sh:14` and `recheck.ps1:15` also refuses it, so it does not discriminate the new check: say so in the row name); `memory/IDENTITY.md` over `memory/identity.md`; a new directory `memory/Journal/d.md` over start `memory/journal/day-001.md`; `memory/Host-Note.md/x.md` over the harness start file `memory/host-note.md` (`true`; the path rule allows it, so this is the row that proves the new check); `skills/Foo.js` and `skills/foo.js` both added; `memory/people/Pike.md` added with `pike.md` kept (`true`); the case-only rename (`delete` `memory/people/pike.md`, `add` `memory/people/Pike.md`: `false`); a start tree that already holds both `memory/a.md` and `memory/A.md`, unchanged (`false`); `memory/journal/day-002.md` next to `day-001.md` (`false`); the same literal path modified (`false`); a 200-path start (`false`); and the `launcher: false` rows `memory/a.MD` over `memory/a.md` and `Memory/Journal/d.md` over `memory/journal/d.md`. ### SC-60j: the symlink swap in `geldar-git` (the known gap; Sonnet)

- **Branch** `scriptorium/sc-60j-nofollow`, worktree `sc-60j`. Commit: `fix(git): hash each memory file from an O_NOFOLLOW descriptor; test the swap`. Depends on: wave 2 only (the packet stays inside `packages/git`; it needs neither the harness nor the tables).
- **Gap (SC-22a scope notes, wave 2 review 1):** `commit.ts` classifies a path with `lstat`, then `git hash-object --stdin-paths` re-opens it by name and follows a symlink. A background process of the agent can swap an allowed path for a symlink between the two steps, so the blob holds the content of any file the process can read (a credential in `/cli-home` or the MCP token in `/proc/self/environ`) as a mode 100644 file, which the gate cannot see (it checks mode and path, not content provenance).
