**What a coder runs (every card; rules 8, 19, 20, 21, 23):** only the packet's own test files, once per edit round, as `./scriptorium.ps1 pnpm vitest run <files>`, then `./scriptorium.ps1 pnpm format` and `./scriptorium.ps1 pnpm typecheck`. Report the run count and every edit made after the last green run as "unverified" (rule 23). Per-test timeouts: 60_000 ms for launcher cases (30_000 default is too low for PowerShell), 120_000 for a docker case, 900_000 for a `beforeAll` image build.

**Models.** Sonnet (`packet-coder` run as `general-purpose`) for harness, security and PowerShell packets; Haiku for the table-driven and mechanical ones (marked on each card). No packet needs more than one session; a Haiku coder that reaches about 60k tokens stops and records what is left (rule 12).

**Findings rule (new for this wave).** A hostile test that finds a real defect in code this packet does not own is committed anyway only if it can pass; otherwise the coder stops, writes the minimal repro in its report under `FINDING` (file, line, the hostile input, the observed outcome) and commits the tests that pass. It never edits a file outside its list (rule 3). The orchestrator writes a fix card (the fix file list and its tests) and dispatches it. Likely findings are named on the cards (for example H-10 size caps, H-04 export attributes), so the orchestrator is not surprised.

**Hostile tests do not run vacuously (review N7).** Every attack asserts three things: the attack script ran (a marker file written by the harness after the script), the specific rejection (a message key or verdict reason, never only "branch unchanged"), and that the host is unchanged (SC-60a's `expectHostUnchanged`).

**The `# H-NN` comment** stays at each enforcing line of `launcher/lib` (wave 5). SC-60 packets do not edit those lines, except the packets that fix named items (SC-60k to SC-60p).

**Pins (verified 2026-11-09 with `gh api` and `npm view`):** this strand adds no package, action or image. SC-63c adds the npm package `yaml` at exact `2.9.1` (published 2026-09-11, 59 days; `npm view yaml dist-tags.latest` is `2.9.1`; 3.0.0 is a prerelease). ### SC-60a: Hostile harness and the parity group (gate)

- **Branch** `scriptorium/sc-60a-hostile-harness`, worktree `sc-60a`. Commit: `test(launcher): add the hostile-session harness and its self-test`. Model: Sonnet. Depends on: wave 5.
- **Files (3):** `launcher/test/hostile/world.ts` (new), `launcher/test/hostile/world.test.ts` (new), `launcher/test/parity.ts` (add the one group `hostile` to both `bash` and `pwsh`). Nothing else. No product code.
- **`world.ts` (target 150 to 220 lines; imports `harness.ts`, never edits it):**
  - `attack(launcher, {id?, mode?, session: string, until?: 'verify' | 'done', env?, setup?(world, player)})` builds `makeWorld()` and `makePlayer()`, writes `session` to a script run through `FAKE_SESSION` with `sh` (cwd is the workspace volume), appends one line `: > "$ATTACK_MARK"` and sets `ATTACK_MARK` to a file in the fake docker root, runs `__prepare`, `__session`, then `__finish` (with `--until verify` when asked), and returns `{world, player, before, after, prepare, session, finish, ran}` where each of the three results is `{status, stdout, stderr}` and `ran` is whether the mark exists. It throws `vacuous attack: the session script did not run` when the script was expected to run and did not.
  - `snapshotHost(world, player)`: the host clone's `HEAD`, branch, `git status --porcelain --untracked-files=all`, `git for-each-ref` of the clone, `git for-each-ref` of the bare `origin`, a sha256 over every file under a `canary/` directory the harness plants outside launcher state (a fake `.ssh/id_x`, a fake `.claude/.credentials.json`, a plain `notes.txt`), and the sorted file list of the state dir without `session/` and `held/` contents.
  - `expectHostUnchanged(before, after, {advancedBranch?: boolean})`: equal on every field; with `advancedBranch` the host `HEAD` and `origin` branch may have moved forward by fast-forward only (used by the benign control).
  - `expectRefusal(result, key, {status})`: `result.stderr` contains `geldar-play: ` plus the text of message `key` read from `launcher/messages.d/*.tsv` (so a renamed text fails the test), the exit status equals `status` (1 refused, 3 held), and stdout and stderr hold no byte 0x1B or 0x07. `expectNoDockerCall(world)`: `calls.log` is empty.
  - `modeOf(path)` and `assertStatePerms(stateDir, id)` for N4: on non-win32, every directory under `<state>/<id>` other than `pub/` has mode 0700 and every file in it is 0600 or 0700, except `pub/allowlist-world.txt` (0644, in a 0755 `pub/`). On win32 the helper returns `skipped` with a visible reason (the state lives under a user-private ACL path).
  - `benign` session text constant (writes `memory/journal/day-001.md`, commits with the noreply identity through `node packages/git/src/cli.ts`) used by the self-test and by each packet as the positive control.
- **Tests (`world.test.ts`, the harness proves itself; `forGroup('hostile')`, 60_000 each):**
  1. benign control: `attack` with the benign session ends saved (status 0), `ran` true, `expectHostUnchanged(..., {advancedBranch: true})` passes.
  2. vacuous guard: a session that is never started (a `session` string with `exit 7` before the mark) makes `attack` throw `vacuous attack`.
  3. host-change detection: a session script that writes into the host clone path (the harness passes it as `HOST_CLONE`; the fake does not isolate) makes `expectHostUnchanged` throw naming `status`; one that edits a canary file makes it throw naming `canary`.
  4. `expectRefusal` fails for a wrong key and for an ESC byte in stderr (feed a fabricated result).
  5. `assertStatePerms` rejects a 0755 session dir and accepts 0700 plus `pub/` (use a hand-built tree; skipped with a reason on win32).
- **Revert checks:** drop the marker line: case 2 fails. Compare only `HEAD` in `snapshotHost`: case 3 fails. Read the message text from a constant instead of the tsv: a test that renames a key fails (add to case 4: assert the key exists in the tsv).
- **Checks:** `./scriptorium.ps1 pnpm vitest run launcher/test/hostile/world.test.ts`, `./scriptorium.ps1 pnpm format`, `./scriptorium.ps1 pnpm typecheck`.

### SC-60b: Case tables and suites for the collision and URL checks (gate)

- **Branch** `scriptorium/sc-60b-tables`, worktree `sc-60b`. Commit: `test(launcher): shared case tables for the case-collision and private-name checks`. Model: Haiku. Depends on: wave 5. Parallel with SC-60a (disjoint files).
- **Files (6):** `launcher/messages.d/53-collision.tsv` (key `recheck_case_collision`, text `The session added a name that differs only by upper and lower case from one you already have.`; owned here so both launcher twins read one file), `launcher/test/collision-cases.json`, `launcher/test/collision-suite.ts`, `launcher/test/mcp-url-cases.json`, `launcher/test/mcp-url-suite.ts`, `launcher/test/tables.test.ts` (new). No product code.
- **The collision rule (decision 28; the one the tables pin).** Define `fold(p)` as ASCII lowercase (the same as the path rule; non-ASCII never passes the path rule). Let `S` be the set of paths in the START tree and `E` the set of paths in the tree at the incoming ref. For a path set `P`, its members are the file paths and every proper directory prefix of each file path (`memory`, `memory/journal`, and so on). The check **rejects** when there are two members `a` and `b` of `S ∪ E` with `fold(a) == fold(b)` and `a != b` (different literal spelling) such that at least one of `a`, `b` is not a member of `S` (the session introduced it). A path that only exists in `S` and is unchanged never collides. A file replacing a directory with the same literal name is not a collision (git handles it and the path rule already limits what may change).
- **`collision-cases.json`:** at least 24 rows `{name, start: string[], add: string[], delete?: string[], collides: boolean}` (the end tree is `start` minus `delete` plus `add`; every path is a plausible allowed path). Required rows: `memory/Identity.md/x.md` over start `memory/identity.md`; `memory/IDENTITY.md` (a file differing only by case) over start `memory/identity.md`; a new directory `memory/Journal/d.md` over start `memory/journal/day-001.md`; `skills/Foo.js` and `skills/foo.js` both added (collision inside the session); `memory/people/Pike.md` over `memory/people/pike.md`; a deep prefix (`Memory/Journal/..`); a rename by case (delete `memory/people/pike.md`, add `memory/people/Pike.md`: the deleted spelling is not in `E`, so **no** collision, `collides: false`, so a legitimate case-only rename is allowed); unchanged start paths only; adding `memory/journal/day-002.md` next to `day-001.md` (false); the same literal path modified (false); `memory/a.md` vs `memory/a.md/b.md` (literal clash, false: not a case issue); `.md` vs `.MD` suffix cases; a 200-path start.
- **`collision-suite.ts`:** `buildCollisionRepo(row, dir)` creates a bare-bones repo **with git plumbing** (`hash-object -w`, `update-index --add --cacheinfo 100644,<blob>,<path>`, `write-tree`, `commit-tree`) so it works on a case-insensitive Windows or macOS file system (a working-tree checkout would merge the spellings), commits the start tree and the end tree with the same author, and returns `{dir, start, ref}`. `runRecheck(launcher, repo, mode)` calls the launcher's own `host_recheck clone start ref mode` the way `bundle.test.ts` case 7 does (`runLib`) and returns `{ok, why}`. `collisionSuite(launcher)` runs every row: `ok === !row.collides`, and for a collision `why` is non-empty and holds no control byte.
- **The URL rule (N3).** The tables pin what `valid_mcp_url` and `Test-McpUrl` must refuse in addition to what they refuse today (no change to the accepted public shapes). New refusals: the single-label host (`localhost`, `intranet`); the names `localhost`, `host.docker.internal`, `gateway.docker.internal`, `kubernetes.docker.internal`; any host ending in `.localhost`, `.local`, `.internal`, `.localdomain`, `.lan`, `.home`, `.home.arpa`, `.corp`, `.intranet`, `.private`, `.invalid`, `.example`, `.onion`; any label starting with `xn--` is allowed; any other name stays allowed. **`.test` stays allowed** because the end-to-end tests use `world.test` and `registry.test` and `.test` never resolves publicly (RFC 6761); the card records this so a later reader does not "fix" it. Exactly the same list applies to `valid_base_url` (it calls `valid_mcp_url`) and to the PowerShell twins.
- **`mcp-url-cases.json`:** at least 40 rows `{url, ok}`: accepted `https://world.example.com/p/mmpr-red` shapes (note `.example` as a TLD is refused, but `example.com` is accepted), `http://world.test/p/x`, port 80 and 443, punycode; refused: each name and suffix above with and without a port, uppercase, trailing dot, `localhost.` , `a..b`, userinfo, IPv4 and IPv6 forms and a numeric host (`2130706433`) as today, a path with a space or `..`, port 8080.
- **`mcp-url-suite.ts`:** `urlSuite(launcher)` calls `valid_mcp_url` through `runLib` (bash sources `lib/player.sh`; pwsh dot-sources `lib/player.ps1`, `Test-McpUrl`) once per row in one process (a single script loops over rows and prints `ok`/`no` per line, so there are two process starts, not eighty) and compares with the table.
- **`tables.test.ts` (no launcher needed):** every collision row is checked by an independent TS reference `refCollides(row)` written in the test file from the rule above (about 25 lines), so the table cannot drift from the stated rule; the URL table is checked by a TS reference of the new refusals plus a regex mirror of today's rules; each table has at least 40 (URL) and 24 (collision) rows and both `true` and `false` outcomes.
- **Revert checks:** flip one `collides` in the JSON: `tables.test.ts` fails. Change the reference to exact-case compare: the identity-over-file row fails. (The product checks are guarded by their implementers, SC-60k to SC-60n.)
- **Checks:** `./scriptorium.ps1 pnpm vitest run launcher/test/tables.test.ts`, `format`, `typecheck`.

### SC-60j: the symlink swap in `geldar-git` (the known gap; Sonnet)

- **Branch** `scriptorium/sc-60j-nofollow`, worktree `sc-60j`. Commit: `fix(git): hash each memory file from an O_NOFOLLOW descriptor; test the swap`. Depends on: wave 2 only (the packet stays inside `packages/git`; it needs neither the harness nor the tables).
- **Gap (SC-22a scope notes, wave 2 review 1):** `commit.ts` classifies a path with `lstat`, then `git hash-object --stdin-paths` re-opens it by name and follows a symlink. A background process of the agent can swap an allowed path for a symlink between the two steps, so the blob holds the content of any file the process can read (a credential in `/cli-home` or the MCP token in `/proc/self/environ`) as a mode 100644 file, which the gate cannot see (the gate checks mode and path, not content provenance). Mitigation chosen (record, do not re-litigate): open each file once with `O_RDONLY | O_NOFOLLOW`, `fstat` the descriptor (regular file, size under the existing cap, `nlink == 1`), read it from that descriptor, and pass the bytes to `git hash-object --no-filters --stdin -w` one file per call (or one `cat-file --batch`-style writer), so classification and hashing use the same open file. A swap after the open changes nothing; a swap before it is a symlink and `O_NOFOLLOW` fails (`ELOOP`).
- **Files (4):** `packages/git/src/commit.ts` (change), `packages/git/src/hash-file.ts` (new: `hashRegularFile`), `packages/git/src/hash-file.test.ts` (new), `packages/git/src/commit-race.test.ts` (new). `commit.ts` gains an optional internal parameter `testHooks?: {afterClassify?: (relPath: string) => void}` that only unit tests pass; the CLI and the MCP server never do (a test asserts `server.ts` and `cli.ts` do not reference it).
- **Tests:** (1) `hashRegularFile` on a regular file gives the same sha as `git hash-object`; on a symlink to a regular file it throws a typed error (skipIf win32, symlinks need rights; run on Linux CI); on a hard-linked file (`nlink` 2) it throws; on a FIFO and a directory it throws. (2) the race: `afterClassify` replaces `memory/journal/day-001.md` with a symlink to a secret file; `commitMemory` reports the path `not_saved` and the secret content is in no blob of the repo (`git cat-file --batch-all-objects` search for a canary string). On win32 the swap uses a file replaced by a junction-free copy so the case is skipped with a reason. (3) hostile content: a file that grows between `fstat` and read is bounded by the cap on bytes read (read at most cap plus one byte, then error). (4) existing `commit.test.ts` stays green.
- **Revert check:** put the `--stdin-paths` call back: case (2) fails. Remove `O_NOFOLLOW`: case (1) symlink fails.
- **Checks:** `./scriptorium.ps1 pnpm vitest run packages/git`, `format`, `typecheck`. Linux-only cases need the CI log (rule 14).
