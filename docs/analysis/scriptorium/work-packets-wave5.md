### Wave 5 shared shape (read first)

**Pins (verified 2026-11-09 on the author machine):** no new npm package, no new image, no new action. The launcher is shell code. Reused pins re-verified: `node:22.23.2-trixie-slim@sha256:c5849ff9...aaa3f6` (`docker buildx imagetools inspect` prints the same index digest) and `ubuntu/squid@sha256:6a097f68...e3bbe029` (same). Tools the launcher needs on the human's machine (D-SC-09): `docker` with Compose v2 (author: Docker 29.1.3, Compose v2.40.3), `git` 2.40 or newer (author: 2.52), `gh` (author: 2.83.2), `tar` (bsdtar ships with Windows 10 and later), and `tmux` only for bash multi-player. Floors: bash 3.2 syntax (macOS), PowerShell 7.4 (author: 7.6.9). A new pin added by a coder must be at least 14 days old (rule 4); SC-55b prints every tool version into the CI log so the runner's versions are on record. `gh repo create --template` was checked against `gh repo create --help` (flags `--template/-p`, `--public`, `--private`, `--clone`).

**Facts measured on the author machine for this wave (the packets rely on them):**
- **Bind mounts on Docker Desktop for Windows show `root:root` mode 0777.** In the kit image, `git -C /player status` fails with `detected dubious ownership` for uid 1000 and for any other uid, even though writes work. `safe.directory` cannot be set from `-c` or the environment. So a bind-mounted workspace cannot work on Windows. (Wave 4 open item 7 expected this.)
- **A named volume mounted over `/player` takes the image directory's owner (`player`, uid 1000).** A helper container run from the kit image can `git clone --no-local --no-hardlinks -c core.autocrlf=false /in/start.bundle` into it from a read-only bind-mounted bundle, `git remote remove origin`, and `git status` is clean, `.git/config` holds no host path. The session then runs as the image's own uid 1000 with no `--user`.
- **Compose merge:** `docker compose -f image/compose/session.yml -f override.yml config` replaces the base `/player` and `/cli-home` volume entries when the override has the same targets, accepts `external: true` named volumes, adds read-only file bind mounts, and passes a variable declared as `GELDAR_MCP_TOKEN:` (no value) from the launcher's environment. **Relative paths in an override resolve against the first file's directory**, so the override uses absolute host paths only.
- `docker build -f image/stub.Dockerfile` reads `image/stub.Dockerfile.dockerignore` in preference to the root `.dockerignore` (tested), which is how the stub variant can see `packages/stub-cli` while the shipped kit image still cannot.
- **Unproven:** Node 22.23.2's `NODE_USE_ENV_PROXY=1` did not send a `fetch` through a local proxy in a quick probe (hung, no output). Do not use it. SC-55a gives the stub its own proxy-aware `fetch`.

**Design decisions made here (the first six need confirmation, see the owner list at the end):**
1. **Workspace = a named volume `geldar-ws-<player_id>`, on every OS.** Created by a helper container from a bundle of START. The session, bundle and verify containers all run as the image's uid 1000. This is one mechanism for bash and PowerShell. It departs from the wave 4 image-contract line "the launcher runs the container with `--user <host uid>`" (**accepted by the orchestrator, review 1 ruling 1**). The departure is recorded where the old lines live: this pass amended `work-packets-wave4.md` lines 43 (the User row), 63 (open item 7) and SC-42a case 8 (it still documents why a bind mount would need a matching uid, reworded). `image/README.md` states no uid line, so it needs no edit. It also departs from the frozen design's "mounts the workspace", so the orchestrator files a decision in the geldar repo `docs/decisions/` (rule 0007) before SC-50b; this repo does not write there.
2. **Host trust anchors are launcher-written files**, never repo content: kit export (`git archive START`), START bundle, compose override, world allowlist, all under `<state>/<player_id>/session/`.
3. **H-14 order follows geldar 0011, not the checklist's wording:** push the verified private ref to `origin`, and only after the push succeeds fast-forward the human's branch. The verify gate and the host re-check sit before both the push and the merge, so the pushed objects are exactly the verified ones in either order; push-first only changes the failure state (a failure before the push changes nothing local, which is what 0011 requires). The push names the verified SHA (`git push origin <sha>:refs/heads/<b>`), and the step 4 clean and ancestry check is the last check before the push. The H-14 line in `docs/launcher-hardening.md` was amended in this spec pass (the only edit to that file here). The threat-model row "fast-forward-only merge and push" must say push first (wave close docs pass), and the orchestrator files the departure from the checklist as a decision in the geldar repo (rule 0007).
4. The launcher is a script plus `lib/` files plus `messages.d/`, and finds the compose and proxy files under `$GELDAR_SHARE` (default: `<repo>/image` when it sits next to the launcher, else `<launcher dir>/share`). How SC-63 packages these is an owner call.
5. **`GELDAR_KIT_IMAGE` is digest-pinned or loudly unsafe (review 1, B2).** The variable must match the same digest regex as `kit_image` (`^[a-z0-9][a-z0-9./-]*@sha256:[0-9a-f]{64}$`). A tag or image-ID form is accepted only when both `GELDAR_INTERNAL=1` and `GELDAR_UNSAFE_IMAGE=1` are set, and then every run prints the `image_unsafe` line (text starts `UNSAFE:`). Anything else is refused with `image_refused` and no docker call. Without the variable the image is `kit_image` from `player.json`, which must match the digest form (H-19). SC-55a and SC-55b (locally built tags) set both variables.
6. **Harness is Claude only in wave 5, and `--cli` is reserved (review 1, B3).** `play`, `setup` and `new` parse `--cli <claude|codex>`; `claude` is the default; `--cli codex` exits 1 with `cli_unsupported` (`Codex is not available yet. Only Claude Code works in this version.`) and no docker call; any other value is a usage error (exit 2). `harness: "codex"` in `player.json` is refused with `harness_unsupported`. `harness_command <cli> <mode>` takes the CLI name as an argument and is the one function SC-71 changes (D-SC-08).
7. **Exit codes:** 0 done; 1 refused or failed with nothing changed; 2 usage error; 3 a session was held (bundle and workspace kept; run `resolve`). All launcher text goes to stderr except `status` output.
8. **Dispatch convention (review 1, B4).** SC-50a's `geldar-play` calls the function `verb_<name>` for verb `<name>` if it is defined (`__prepare` calls `verb___prepare`); an undefined verb prints `not_yet` and exits 2. Each lib file defines its own `verb_*` functions and appends its group to `GP_GROUPS`. Later bash packets therefore add only lib files and never edit `geldar-play`, except where their Files list says so (SC-51b `play`, SC-52a `new`/`setup`, SC-52b `resolve`/`archive`/`status`). PowerShell uses the same rule with `Invoke-Verb` and `Verb-<name>` functions. `verb___finish` lives in `lib/finish.sh` and calls `finish_session`, which takes `--until verify` (a test-only stop point). SC-51a ships a minimal `lib/finish.sh` (bundle, verify, re-check, the stop) and SC-51b extends the same function in the same file (listed in its Files), so exactly one `verb___finish` exists.
9. **Test-only variables (review 1, B13).** One list: `GELDAR_INTERNAL`, `GELDAR_TEST_HOOK_AFTER_CLEAN`, `GELDAR_SLEEP`, `GELDAR_KEEP_PROXY_LOG`, `GELDAR_TMUX`, `GELDAR_WT`, `GELDAR_EXTRA_COMPOSE`, `GELDAR_UNSAFE_IMAGE`, `GELDAR_PRIVATE_SHARDS_TEST`, `GELDAR_HELPER_TIMEOUT_SEC` (replaces every product timeout, decision 13), `GELDAR_TOOL_PATH` (a directory that replaces `PATH` for the `need` checks), the `GELDAR_STUB_` passthrough, and the internal verbs `__prepare`, `__session`, `__finish` and `__bounded` (review 3, B2) plus `--until`. Every one is read only when `GELDAR_INTERNAL=1`. A core test (SC-50a) shows that without `GELDAR_INTERNAL`, each has no effect (a set `GELDAR_STUB_X` does not appear in the generated override; a hook script is not run). `GELDAR_DOCKER`, `GELDAR_GH`, `GELDAR_GIT`, `GELDAR_STATE_DIR`, `GELDAR_PLAYERS_DIR` and `GELDAR_SHARE` stay ordinary seams; they execute binaries or read paths from the human's own environment, which is documented.
10. **Prerequisites table (review 1, N8).** SC-50a defines which verb calls `need` for what, and the hint text: `docker` (all verbs but `status`; `docker compose version` must also succeed, message names Compose v2), `git` (all verbs; version 2.40 or newer, else a version message), `tar` (every verb that exports), `perl` (every verb that prints text from a repo or a bundle, so all but `status`), `tmux` (bash multi-player only), `gh` (`new`, `archive`). `node` is not needed on the host. The hint (the second `%s` of `missing_tool`) for every tool, including `tar`, `docker` and `perl`, is in the appendix. Template README text for these is SC-70.
11. **World configuration (review 1, B9).** The real world's address and the private-only shard list live in one data file shipped with the launcher, `launcher/config/world.conf` (key=value, read as data, never sourced), with documented placeholders: `mcp_base=` and `private_only_shards=`, both blank, with the comment `OWNER INPUT REQUIRED`. See SC-52a. These are owner inputs for SC-72, listed in the ledger.
12. **Real use needs SC-63 (review 1, N9).** `template/player.json` carries empty `kit_image` and `kit_version`, which `new` keeps and SC-63 fills. `read_player` rejects the empty `kit_image` (`bad_player_json`), so a player made by `new` cannot be played until SC-63, unless a valid `GELDAR_KIT_IMAGE` is set (decision 5). With a valid override `player.json`'s `kit_image` is not consulted at all, so the empty template value does not break SC-55b, whose flow starts with `new`; the digest form without INTERNAL prints no warning. This is accepted and stated here.
13. **Product timeouts (review 2, B5).** Every wait in product code is bounded by one function `run_bounded <seconds> <cmd...>` in `lib/common.sh` (bash, no dependence on `timeout`) and its PowerShell twin `Invoke-Bounded` (SC-53a): helper containers `workspace-init` 120 s, `bundle` 300 s, `verify` 300 s; network git (`pull`, `fetch`, `push`) 120 s; each `gh` call 60 s; `GIT_TERMINAL_PROMPT=0` so a credential prompt fails instead of hanging. On expiry the launcher runs `docker kill` then `docker rm -f` on the named container (`geldar-<role>-<id>-<pid>`), and the result is a refusal (`workspace-init`, `pull`, `gh`: nothing changed) or a hold (`bundle`, `verify`, `fetch`, `push`: the commits are kept). Under `GELDAR_INTERNAL=1`, `GELDAR_HELPER_TIMEOUT_SEC=<n>` replaces all of these bounds so tests finish in seconds. **Process tree (review 3, N3):** `run_bounded` kills the whole process group, not only its child: bash runs the command as a job under `set -m` (its own group; no `setsid`, which stock macOS lacks; bash 3.2 compatible), polls for exit, and on expiry sends `kill -TERM -- -<pgid>` then `-KILL`. PowerShell `Invoke-Bounded` kills the process tree (`Process.Kill($true)`). Tests assert that no process of the killed command is left (the fake writes its pid to a file; `kill -0` on it must fail, and the PowerShell tests check `Get-Process -Id`). Form: `run_bounded <seconds> [--container <name>] <cmd...>`; with `--container`, expiry also runs `docker kill` then `docker rm -f` on that name. Hooks and `FAKE_SESSION` scripts are run with `sh <script>` (under pwsh too).

**State** (`GELDAR_STATE_DIR`, else `${XDG_STATE_HOME:-$HOME/.local/state}/geldar` for bash and `%LOCALAPPDATA%\geldar` for PowerShell): per player `<state>/<id>/` holds `clone` (path of the host clone), `branch`, `start` (H-03), `mode` (`play` or `setup`), `lock/` (a directory made with `mkdir`; its existence means a launch is running), `token` (mock world bearer, mode 0600), `held/` (`bundle.bundle` and `info` while a session is held), and `session/` (`export/`, `start.bundle`, `bundle.bundle`, `allowlist-world.txt`, `override.yml`, `running`). `GELDAR_PLAYERS_DIR` (default `~/geldar-players`) is where `new` clones.

**Environment seams** (read from the human's environment only): `GELDAR_DOCKER`, `GELDAR_GH`, `GELDAR_GIT` (default the plain names), `GELDAR_STATE_DIR`, `GELDAR_PLAYERS_DIR`, `GELDAR_SHARE`, `GELDAR_KIT_IMAGE`, and the passthrough prefix `GELDAR_STUB_` (any such variable that is set is copied into the session container; the real image has no stub, so it does nothing there).

**Docker objects** (all created by the launcher, every `docker run` carries `--label geldar.role=<role>`): volumes `geldar-ws-<id>` and `geldar-cli-<id>-claude` (H-07); compose project `geldar-<id>`; roles `workspace-init`, `session`, `bundle`, `verify`. Helper, bundle and verify containers: `--rm --cap-drop ALL --security-opt no-new-privileges -e HOME=/tmp -e GIT_CONFIG_GLOBAL=/dev/null -e GIT_CONFIG_NOSYSTEM=1 -e GIT_NO_REPLACE_OBJECTS=1`, no `--user` (image default uid 1000).

**Message rules:** one line each, plain, to the human (the Patron). The text lives only in `launcher/messages.d/*.tsv`; both launchers print `geldar-play: <text>` to stderr through one function (`say <key> [args]` / `Say`). Anything that came from a bundle or a repo (subjects, paths, reasons) goes through the control-character filter first (H-16): **one behavior for both launchers (review 1, B8):** replace each C0 control (0x00-0x1F, including tab and newline), DEL and each C1 control (the code points U+0080 to U+009F) with a single space, then collapse the result to one line: a CR LF pair gives two spaces (runs are not squeezed) and a trailing newline is dropped, so `a`, CR, LF, `b` gives `a  b`. C1 is matched as code points, never as bytes: bytes 0x80-0x9F are continuation bytes of ordinary UTF-8 characters, so a byte-wise delete corrupts valid text (the euro sign would lose its middle byte). PowerShell uses `[regex]::Replace($s, '[\x00-\x1F\x7F-\x9F]', ' ')`. Bash uses `perl -CSD -pe` with the same class (measured on the author machine: it keeps the euro sign, an accent and CJK and replaces `C2 9B`; `perl` ships with Git for Windows, macOS and Linux and is in the prerequisites table). BSD or C-locale `sed` is not reliable and is not used. PowerShell sets `[Console]::InputEncoding`, `[Console]::OutputEncoding` and `$OutputEncoding` to `[System.Text.UTF8Encoding]::new($false)` at startup and reads native output as UTF-8 (the console default here is code page 437, which turns the three bytes of the euro sign into three characters). Verdict reasons are never printed raw: the launcher prints its own text for the 16 fixed identifiers in work-packets.md § Wave 2 contract notes and a generic line for anything else.

**Test support (SC-50a builds it; every later packet uses it):**

On win32 the harness writes a `docker.cmd` that calls `bash fake-docker.sh`; best effort.
- `launcher/test/parity.ts`: `export const enabled = { bash: [...], pwsh: [...] } satisfies Record<string, string[]>`. Group names: `core`, `pre`, `session`, `bundle`, `finish`, `new`, `setup`, `commands`. A bash packet adds its groups to `bash`, its twin to `pwsh` (shared file, one-line change each, rule 13). A group in `enabled.pwsh` means the pwsh launcher passes the same test file the bash one does; no test is rewritten for pwsh.
- **Fake docker executes the launcher's own scripts (review 1, B6).** For `docker run` of a helper role (`workspace-init`, the H-05 check, `bundle`), the fake takes the `sh -c` script string from the launcher's argv, substitutes the mount points (path-prefix tokens only: `/in/` to the host session dir, `/player` to the volume dir, `/tmp` to a scratch dir, never inside longer names such as `/init`, `/input` or `/tmp/c`; `-v src:dst[:ro]` is split from the right so a Windows drive colon is harmless) and runs it with the real `sh` and `git`, and nothing else. It never does the security-relevant work itself. So dropping `git remote remove origin` or `--no-hardlinks` from the launcher's string changes the fake's result and the H-05 test fails. A role or flag set the fake does not know exits 99. The `verify` role runs the real `geldar-verify`. A harness `afterEach` scans `calls.log` and asserts two things. (a) Every helper `docker run` argv carries `--cap-drop ALL` and `--security-opt no-new-privileges`. (b) For `compose run` (it has no `--security-opt` flag; the options come from `session.yml`) it asserts on the merged `compose config` that SC-50c case 1 already parses: the `session` service has `cap_drop: [ALL]`, `security_opt` containing `no-new-privileges:true`, no `privileged`, no `network_mode`; the Squid service is not checked for these (it has `cap_add: [SETUID, SETGID]` by design). The deny list applies to both kinds of call: none carries `--privileged`, `--network host`, a `--pid` option, `--user 0`, `docker.sock`, `-v /:` or the home directory. Host git calls: the harness sets `GELDAR_GIT` to a logging wrapper that appends argv to `$GELDAR_TEST_GITLOG`, and all host-side assertions (no force, fsck flags) read that file, not `calls.log`. **Layered (review 3, N7):** a git that must sleep is the same wrapper configured by `FAKE_GIT_SLEEP_ON=<subcommand>` (it logs, then sleeps 30 s with SIGPIPE ignored, for that subcommand only; all others exec the real git), never a replacement, so the log assertions stay in force in timeout tests. A fake that must block (a role with `FAKE_ROLE_SLEEP`, or a closed-pipe case) ignores SIGPIPE (`trap '' PIPE`), so `docker kill` is the only way out. The harness runs under `umask 077`. `GELDAR_STATE_DIR` and the temp paths contain no `:`, `,` or `$`.
- `launcher/test/fake-docker.sh` (POSIX sh) plus `fake-docker.d/NN-<role>.sh`, one file per packet that adds a role. It stands in for `docker` when `GELDAR_DOCKER` points at it; state under `$FAKE_DOCKER_ROOT` (`vol/<name>/` directories, `calls.log` with one tab-separated argv per line, so tests assert the exact docker calls). Unknown subcommands exit 99 so a missing role fails loudly. It runs real `git` and, for the verify role, the real `geldar-verify` (`node packages/verify/src/cli.ts`), so the gate in these tests is the shipped one. For the session role it executes `$FAKE_SESSION` (a script path) with cwd the workspace volume directory, standing in for the agent: that script may do anything, including attacks (SC-60 builds on it).

- `launcher/test/path-cases.json` (SC-51a): about 40 `{path, mode, allowed}` cases. A TS test checks every case against `isAllowedPath` from `@geldar/scriptorium-path-rule`, so the table cannot drift from the gate; the bash and pwsh host re-check functions run the same table.

### SC-50a — Launcher infrastructure: dispatcher, messages, test harness, fake docker

- **Branch** `scriptorium/sc-50a-infra`, worktree `sc-50a`. Commit: `feat(launcher): the geldar-play dispatcher, message table, test harness and fake docker`. Repo S. Depends on: wave 4.
- **Files (8):** `launcher/geldar-play`, `launcher/lib/common.sh`, `launcher/messages.d/00-core.tsv`, `launcher/test/harness.ts`, `launcher/test/parity.ts`, `launcher/test/fake-docker.sh`, `launcher/test/fake-docker.d/10-workspace.sh`, `launcher/test/core.test.ts`.
- **`geldar-play`** (`#!/usr/bin/env bash`, `set -u`, no `set -e`; bash 3.2 syntax only: no `declare -A`, `mapfile`, `${x,,}`, `&>>`): resolves its own directory with `cd "$(dirname "$0")" && pwd -P` (follow a symlinked install by resolving `$0` with `readlink` in a loop), sources `lib/*.sh` in name order, loads every `messages.d/*.tsv`, then dispatches the verb. Verbs: `new setup play resolve archive status help --version --capabilities`. Unknown or missing verb: message `usage`, exit 2. ## The PowerShell launcher (SC-53a to SC-54b)

Every packet here mirrors the bash packet with the same suffix. Rules for all of them:
- **The same test files run.** The packet adds its groups to `parity.ts` `enabled.pwsh`; the bash test file for that group then runs against `pwsh -NoProfile -File launcher/geldar-play.ps1 <args>` too. A packet is done only when those files pass for `pwsh` (count the tests that ran, not skipped, in the report). Do not copy or fork a bash test; if a test is wrong for PowerShell, fix the shared test and say so.
- **Messages come from `launcher/messages.d/*.tsv`** (read with `Get-Content`/split on tab), never retyped. A message missing there is added to the same `.tsv` as the bash packet's (it already has it), not to a ps1 file.
- **Files** `launcher/geldar-play.ps1` and `launcher/lib/*.ps1` (dot-sourced from `$PSScriptRoot`), `#requires -Version 7.4`, `Set-StrictMode -Version Latest`, `$ErrorActionPreference = 'Stop'` around PowerShell cmdlets but **native commands are checked by `$LASTEXITCODE` after every call** (a native failure never throws by itself). Never `Invoke-Expression`. Arguments to native commands are passed as an array, never a built string.
- **Windows specifics:** state in `%LOCALAPPDATA%\geldar`, `GELDAR_STATE_DIR` honored. Paths given to Docker are the native `C:\...` form; compose override files use absolute paths, written with forward slashes inside double-quoted YAML scalars. The token and `start` files are created with `[System.IO.File]` and restricted with `icacls` to the current user where the bash version uses mode 0600. Binary output (the bundle) is **never** passed through the PowerShell pipeline (it re-encodes as text): use `System.Diagnostics.Process` with `StandardOutput.BaseStream` copied to a `FileStream` in a loop that stops at 52428801 bytes and kills the process. `tar` is Windows' `tar.exe` (bsdtar); `git archive --format=tar` is piped into it through a `Process` pair or a temp file, not `|`. Scripts run as `pwsh -NoProfile -File`, so the execution policy is the user's; the release signs the file (SC-63).
- **Line endings** LF in `.ps1` files (`.gitattributes` already does this); CRLF only for `*.bat/*.cmd`.
- A PowerShell packet that finds a bash behavior it cannot reproduce stops and reports (an owner item), it does not weaken the shared test.
