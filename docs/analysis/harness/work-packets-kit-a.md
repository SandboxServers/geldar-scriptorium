## Shared contract (every card builds to these names)

- **Harness values** (`player.json` `harness`, `GELDAR_HARNESS`, stamps): `claude`, `chatgpt`, `local`.
- **New packages.** `packages/mind-loop` = `@geldar/scriptorium-mind-loop`, source only, exports `./src/index.ts`, imported as `import { ... } from '@geldar/scriptorium-mind-loop'`. `packages/local` = `@geldar/scriptorium-local`, binary `geldar-local` with verbs `run` and `check`. `packages/chatgpt` keeps sign-in, `completed()`, `runRound()` (a thin wrapper) and `ResponsesTransport`.
- **mind-loop surface.** Types `Item`, `Tool` (`call(args): Promise<Block[]>`), `ToolSpec` (name, description, parameters), `Block` (`{type:'text',text}` or `{type:'image',mimeType,data}`), `ToolCall` (`{id,name,arguments}` with `arguments` the raw JSON text), `ToolReturn` (`{call, blocks}`), `Completion` (`{text, calls, usage?}`), `Usage` (`{input,cached,output}`: uncached input, cached input, output), `Transport` (`send(input): Promise<Completion>`), `LoopRound`. - **Stream items the owned loops print** (one JSON per line, read by `summarizeStream` and the supervisor): `{type:'assistant', message:{content:[...]}, usage?}` and a last `{type:'result', is_error, num_turns, total_cost_usd:0, cost_source, result?, usage:{input_tokens,cached_input_tokens,output_tokens}, stop_reason?}`. `cost_source` is `unavailable_subscription` (chatgpt) or `not_metered_local` (local). `stop_reason` is one of `max_turns`, `context_too_small`, `invalid_tool_calls`, `transport_error`.
- **Supervisor state files** (volume `geldar-sup-<id>`): `costs.csv` columns `run,utc,turns,cost,harness,model` (no header); new `tokens.csv` columns `run,utc,input,cached,output,harness,model` (no header; `input` is uncached input); `status.json` gains `harness`, `model`, `tokens_today`; `checkpoint-request` holds one JSON line `{"run":N,"harness":"...","model":"..."}`.
```ts
// errors.ts
export class MindError extends Error {
  constructor(message: string, readonly reason: string = 'error') { super(message); }
}
// transport.ts
export type Block = { type: 'text'; text: string } | { type: 'image'; mimeType: string; data: string };
export type Fetch = typeof fetch;
export interface ToolSpec { name: string; description: string; parameters: Record<string, unknown> }
export interface ToolCall { id: string; name: string; arguments: string }
export interface ToolReturn { call: ToolCall; blocks: Block[] }
export interface Usage { input: number; cached: number; output: number }
export interface Completion { text: string; calls: ToolCall[]; usage?: Usage }
export interface Transport { send(input: { prompt: string } | { results: ToolReturn[] }): Promise<Completion> }
// loop.ts
export interface LoopRound {
  transport: Transport; prompt: string; maxTurns: number; tools: Tool[];
  emit(item: Item): void; costSource: string;
}
export async function runLoop(round: LoopRound): Promise<void>
```

  `Tool.call` and `Tool` stay as in HC-05 here (`Promise<unknown>`) but add `Block` to the contract: HC-06b switches `Tool.call` to `Promise<Block[]>`; until then `runLoop` passes whatever the tool returned to the transport inside `blocks` via a cast; keep `blocks: Block[]` typed and cast once, commented.
  `runLoop` algorithm (port of `runRound`, in this order): `turns=0; text=''; total={input:0,cached:0,output:0}; byName=Map`; first `completion = await transport.send({prompt})`; loop `while (true)`: `turns++`; add `completion.usage` into `total`; `if (completion.text) text = completion.text` (the last non-empty text persists across turns, as today); emit the assistant item (`content` = optional `{type:'text',text}` plus one `{type:'tool_use',name,id,input:arguments}` per call; `usage` as `{input_tokens: u.input, cached_input_tokens: u.cached, output_tokens: u.output}` when present); if no calls, emit the success result and return; if `turns >= maxTurns` throw `new MindError('The round reached GELDAR_RUN_MAX_TURNS.', 'max_turns')`; else for each call: look the tool up by name, `JSON.parse(call.arguments)`, require `record(args)` and a non-empty `call.id`, run `await tool.call(args)`; any failure (unknown tool, bad JSON, throw) yields `[{type:'text',text:'That tool call could not be completed.'}]`; then `completion = await transport.send({results})`. ## HC-07: The `chat` transport (chat completions, function tools)

- **Branch** `scriptorium/hc-07-chat-transport`, worktree `.claude/worktrees/hc-07`. **Depends on** HC-06a (the interface), HC-06b (neutral `Block`s).
- **May edit:** `packages/mind-loop/src/chat.ts` (new), `chat.test.ts` (new), `index.ts`. **Must not edit:** the loop, `packages/chatgpt`.
- **Decision (stated): non-streaming** (`stream: false`). Why: the loop shows no partial output, so streaming buys nothing; tool-call deltas are assembled differently by vLLM and Ollama and that is the likeliest place for the two servers to differ; a single JSON reply is validated whole. Cost: the connection carries no bytes while the model generates, so the request has a 10 minute timeout (as the Responses transport has) and `max_tokens` bounds each reply (a looping model cannot run forever).
- **Behaviour.** `export class ChatTransport implements Transport`, constructor `ChatConfig = {baseUrl: string; apiKey?: string; model: string; instructions: string; tools: ToolSpec[]; maxOutputTokens?: number; request?: Fetch}`. It keeps `messages: ChatMessage[]` starting `[{role:'system', content: instructions}]`. `send({prompt})` pushes `{role:'user', content: prompt}`; `send({results})` pushes one `{role:'tool', tool_call_id: call.id, content}` per result, where `content` is the text blocks joined with a newline and each image block replaced by the line `[image omitted: this model reads text only]` (HC-12 replaces this for `images: true`); an empty content becomes `No result.`. Request:

```ts
POST `${baseUrl.replace(/\/+$/, '')}/chat/completions`, redirect 'error', signal AbortSignal.timeout(10*60_000),
headers { 'Content-Type': 'application/json', ...(apiKey ? { Authorization: `Bearer ${apiKey}` } : {}) },
body JSON.stringify({ model, messages, stream: false, max_tokens: maxOutputTokens ?? 2048,
  tools: tools.map(t => ({ type: 'function', function: { name: t.name, description: t.description, parameters: t.parameters } })) })
```

  Never send `tool_choice`, `parallel_tool_calls`, `strict`, `temperature`, `response_format`, `stream_options` or `store`; send `tools` only when the list is non-empty. Reply handling: `!res.ok` throws `new MindError(`The model server returned HTTP ${res.status}.`, 'transport_error')` (never the body); a body that is not JSON or has no `choices[0].message` throws `MindError('The model server sent a reply the kit could not read.', 'transport_error')`; `finish_reason === 'length'` together with tool calls throws `MindError('The model server cut the reply short.', 'transport_error')`. `message.tool_calls[]` become `ToolCall`s: `id` is the server's string id or `call_${n}` (an incrementing counter, also used when two calls share an id), `name = function.name`, `arguments` = the string, or `JSON.stringify` of it when the server sent an object. The assistant message is pushed to `messages` as `{role:'assistant', content: text, tool_calls: [{id, type:'function', function:{name, arguments}}]}` (omit `tool_calls` when none). `usage` maps `prompt_tokens` to `input`, `0` to `cached` and `completion_tokens` to `output` when present. ## HC-13a: `runCheck` conformance probe and `geldar-local check`

- **Branch** `scriptorium/hc-13a-local-check-lib`, worktree `.claude/worktrees/hc-13a`. **Depends on** HC-08a, HC-10, HC-11, HC-12 (it exercises the real transport).
- **May edit:** `packages/mind-loop/src/check.ts` (new), `check.test.ts` (new), `index.ts`, `packages/local/src/cli.ts`. **Must not edit:** the transport or loop.
- **Behaviour.**

```ts
export type CheckStep = 'models' | 'tool_round' | 'context' | 'image';
export interface CheckResult { step: CheckStep; ok: boolean; code: string; message: string }
export interface CheckConfig { baseUrl: string; apiKey?: string; model: string; contextTokens: number; images: boolean; request?: Fetch }
export async function runCheck(cfg: CheckConfig): Promise<CheckResult[]>   // runs the four steps in order; every step is attempted
```

  Steps (each result's `message` is a fixed sentence from one table `CHECK_MESSAGES: Record<code,string>`, never a server body; `code` is `ok` or the failure code):
  1. `models`: `GET {base}/models`; a non-200 is `models_http` ("The server did not list its models (HTTP status). Check the address, the key and that the server is running."); a body without a `data[].id` list is `models_unreadable`; the declared model must equal an id, or, when it has no `:`, equal `<model>:latest` (`models_missing`: "The server does not list the declared model. Use a name from its model list.").
  2. `tool_round`: run `runLoop` with a `ChatTransport` (validation on, `maxTurns: 3`) and one scripted tool `geldar_check_echo` with schema `{type:'object', properties:{word:{type:'string'}}, required:['word'], additionalProperties:false}` whose `call` records its arguments and returns `[{type:'text', text:'pong'}]`; the prompt is `Call the tool geldar_check_echo with the word "ping", then tell me what it returned.` Pass when the tool ran exactly once with a string `word` and the loop ended `is_error:false`. Failures: `tool_not_called` ("The model answered without calling the tool. The server may need its tool-call parser turned on, or the model may not support tools."), `tool_args_invalid`, `tool_round_failed` (any `MindError`).
  3. `context`: build a prompt with the fixed secret word `KESTREL` in the first sentence, then numbered filler sentences until `estimateTokens(prompt) >= contextTokens - reserve - 200` (reserve as in HC-10), then `What was the secret word? Answer with that word only.` Send it as one chat call with `max_tokens` 32. Pass when the reply contains `KESTREL` (case-insensitive) and, when the server reports `usage.prompt_tokens`, that number is at least 60 percent of the estimate. Failures: `context_http` (the server refused: it is smaller than declared, message names `context_tokens`), `context_truncated` ("The server answered without the start of the prompt. It may be cutting the prompt: raise the server's context size or lower context_tokens.").
  4. `image`: when `images` is false the step is `{ok:true, code:'skipped', message:'Images are off for this player.'}`; otherwise send one chat call with a 1x1 PNG data URL (a fixed base64 constant in the file) and the text `Reply with the word ok.`; any HTTP error is `image_rejected` ("The server or model does not accept images. Set images to false for this player.").
  `cli.ts` gains verb `check`: `readLocalConfig(process.env)`, run `runCheck`, print one line per step `<step>: ok` or `<step>: FAILED <message>` to stdout, exit 0 only if all pass. It prints no URL, key or server body.
- **Tests (`check.test.ts`, a small fake server as a `request` function).** A good server passes all four; each failure mode above is produced once and returns its code (model absent, `:latest` match, no `tool_calls` in the reply, wrong argument type, a 400 on the long prompt, a reply without `KESTREL`, `prompt_tokens` far below the estimate, a 400 on the image); `images:false` never sends an image; a result `message` never contains the key sentinel or the fake server's secret body text; the filler length is within the budget by `estimateTokens` (revert the canary check and the truncation case fails).
- **Checks:** `./scriptorium.ps1 pnpm lint`, `./scriptorium.ps1 pnpm typecheck`, `./scriptorium.ps1 pnpm vitest run packages/mind-loop packages/local`, `./scriptorium.ps1 pnpm check:repo`.
